## 一、总开发边界

本轮目标是交付两个可复现的研究型工程原型，不是生产平台，也不以论文级 SOTA 为验收标准。

“仓库可以运行”只代表基础工程可行，不代表项目完成。只有满足本文对应项目的全部验收项，才可以标记为阶段完成。

共同要求：

- 新机器能够按文档重新配置环境。
- 核心流程能够通过脚本复现，不依赖口头记忆或不可追踪的手工操作。
- 原始结果、失败结果和无效实验均保留并明确区分。
- 报告中的数字能够追溯到原始文件。
- 代码、配置和文档进入 GitHub；密钥、环境、大模型和大数据不进入 Git。
- 数据盘上的数据、模型和 checkpoint 有明确路径及用途说明。

## 二、项目一：Trace 驱动 Agent 自进化

### 2.1 最终目标

证明 Trace 可以驱动真实失败诊断，并形成一次可复现的 Agent 改进闭环：

```text
轨迹采集 → 失败诊断 → 改进策略 → 重新运行 → 对照评测
```

### 2.2 必须交付

- [ ] 提供一条命令完成轨迹采集、格式转换、失败诊断和报告生成。
- [ ] 建立互不重叠的开发集与留出测试集。
- [ ] 固定至少一个零样本基线和一个改进方案。
- [ ] 在留出测试集上统一比较根因类别、失败步骤、token、成本和耗时。
- [ ] 将诊断结果转化为一次实际 Agent 改进，例如提示词、工具约束或执行策略调整。
- [ ] 在同协议任务上重新运行改进前后的 Agent。
- [ ] 报告任务成功率变化，并检查其他任务是否发生性能回退或成本异常增加。
- [ ] 保存可复现实验脚本、配置、原始结果和最终报告。

### 2.3 完成判定

项目一达到阶段完成，需要同时满足：

1. 留出测试集从未用于提示词或规则调优。
2. 改进方案与基线使用相同的模型、任务和评测协议。
3. 至少完成一次“发现失败—提出改进—重新评测”的闭环。
4. 无论结果提升、持平或下降，都如实落盘和报告。

项目一不以某个预设准确率作为硬性验收条件，因为当前真实失败样本规模较小；验收重点是实验划分正确、闭环真实发生、结论与证据一致。若结果没有提升，只能结论为“闭环工程可行但方法尚未产生收益”。

### 2.4 本轮非目标

- 不训练新的失败诊断大模型。
- 不执行大规模在线 RL。
- 不建设 Web 平台、多用户系统或生产部署体系。
- 不宣称通用自进化能力或 SOTA。

## 三、项目二：Coding Agentic RL

### 3.1 最终目标

证明 Coding Agent 轨迹能够被严格采集、独立复验、清洗并用于一次最小训练闭环：

```text
净化任务 → Agent rollout → 隐藏测试 → 轨迹清洗
→ SFT/GRPO smoke → checkpoint → 训练后回归评测
```

### 3.2 SWE-smith Pilot 必须交付

- [ ] 完成固定的 20 条 SWE-smith 任务。
- [ ] 所有模型运行仓库满足单提交、`HEAD^` 不可访问。
- [ ] 每条任务保存轨迹、补丁、完整隐藏测试结果、reward、token、成本和完整性状态。
- [ ] 污染、泄漏或无法复验的运行永久排除出成功率和训练数据。
- [ ] 自动化“净化仓库 → rollout → 独立评测 → 完整性判定 → 汇总”流程。
- [ ] 汇总文件可以由原始结果重新生成。

### 3.3 数据交付

- [ ] 导出可信成功轨迹。
- [ ] 导出可信失败轨迹。
- [ ] 单独生成无效轨迹隔离清单。
- [ ] 每条训练样本能够追溯到原始任务、补丁和独立测试证据。
- [ ] 无效轨迹不得进入 SFT 或 GRPO 数据。

### 3.4 最小训练闭环必须交付

- [ ] 在数据盘安装并验证 `rllm[verl]` 训练环境。
- [ ] 选择能够在现有 GPU 资源上运行的本地开源小模型。
- [ ] 完成一次 LoRA SFT smoke。
- [ ] 完成一次小规模 GRPO/Agentic RL smoke。
- [ ] 验证 reward 确实进入训练流程，模型参数确实更新。
- [ ] 保存并重新加载 checkpoint。
- [ ] 使用未参与训练的任务完成训练前后同协议评测。
- [ ] 保存训练配置、日志、资源使用、checkpoint 信息和最终报告。

### 3.5 完成判定

项目二达到本轮完成，需要同时满足：

1. 20 条严格 Pilot 全部结束并完成独立评测。
2. 数据清洗与完整性门禁可以自动运行。
3. SFT 和 GRPO 至少各完成一次真实的最小训练运行，而不是只完成配置或导入测试。
4. checkpoint 能够保存、加载并用于评测。
5. 有训练前后的同协议结果，无论性能是否提升都如实报告。

本轮只要求训练闭环真实可运行，不强制要求性能显著提升。若数据量不足或结果无提升，只能结论为“训练系统工程可行”，不能宣称“RL 提升了 Coding Agent”。

### 3.6 本轮非目标

- 不要求完成 500–2,000 条正式规模 SFT 数据采集。
- 不进行大模型全参数训练。
- 不建设多机多卡训练平台。
- 不以 SWE-bench 排行榜成绩作为验收条件。
- 不建设生产推理服务。
