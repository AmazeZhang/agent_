# OpenSearch-VL 简历数字来源与使用边界

> 建立日期：2026-08-21
> 本地审计版本：`c5c02a49780e26ae9cb6f1fb56731d1e594d59f0`
> 论文版本：arXiv:2605.05185v1（2026-05-06）
> 用途：区分作者论文结果、开源仓库声明、公开数据统计和个人复现结果，防止在简历、面试和实验报告中混用。

## 1. 结论

此前简历模板中的以下结果均来自 OpenSearch-VL 作者论文或官方 README，并非当前个人复现结果：

```text
53.7 → 64.6 → 67.6 → 67.7 → 69.1 → 71.8
七项 benchmark 平均分：42.0 → 56.6
```

数据规模中：

- `36,592` 条 SFT 专家轨迹和平均 `6.3` 次工具调用来自论文与官方 README；
- `SearchVL-RL-8K` 是官方数据集名称；此前下载公开 JSONL 后逐行统计为 `7,992` 条，这是本地数据审计结果，不是论文中的精确声明；
- 当前本地仓库没有保存个人 SFT/RL checkpoint、训练日志或个人评测结果，因此还不能把作者数字标记为“个人复现结果”。

## 2. 来源等级

后续所有数字使用以下标签：

| 标签 | 来源 | 可以怎样表述 |
|---|---|---|
| `P` | 作者论文 | “论文报告”“作者实验显示” |
| `R` | 官方 README、模型卡或仓库配置 | “开源仓库披露”“官方配置为” |
| `D` | 对公开数据或代码进行的本地审计 | “对公开数据逐行统计”“源码审计发现” |
| `L` | 我们在固定代码、数据和协议下实际运行的结果 | 可以写为“个人复现”“实验达到” |

只有 `L` 级数字可以无前缀地作为个人项目结果写入最终简历。`P/R/D` 可以用于项目背景、复现目标和面试中的论文理解，但不等于个人训练成绩。

### 3.2 三项消融结果

这组数字来自论文 Table 3(b)，评测范围只有 `SimpleVQA、InfoSeek、FVQA` 三项，不是七项 benchmark 平均分。

| 阶段 | SimpleVQA | InfoSeek | FVQA | 三项平均 | 等级 |
|---|---:|---:|---:|---:|---|
| Qwen3-VL-8B Base | 52.0 | 50.3 | 58.7 | 53.7 | `P` |
| + SFT only | 66.1 | 62.4 | 65.3 | 64.6 | `P` |
| + Vanilla GRPO | 68.8 | 66.5 | 67.4 | 67.6 | `P` |
| + GRPO Hard Masking | 68.3 | 67.9 | 66.9 | 67.7 | `P` |
| + Fatal Masking only | 69.7 | 68.3 | 69.2 | 69.1 | `P` |
| + Fatal Masking + One-sided Clamp | 71.6 | 72.4 | 71.5 | 71.8 | `P` |

由表中可以合法推导：

- 作者实验中 SFT 相对 Base 提升 `10.9` 个平均点；
- Vanilla GRPO 相对 SFT 提升 `3.0` 个平均点；
- Fatal Masking + Clamp 相对 Vanilla GRPO 提升 `4.2` 个平均点；
- Hard Masking 相对 Vanilla GRPO 只提升 `0.1` 个平均点。

这些推导仍然属于 `P` 级作者实验结论。

### 3.3 七项主结果

论文 Table 2 使用统一 Pass@1 + GPT-4o judge，在以下七项 benchmark 上计算平均分：

```text
SimpleVQA / VDR / MMSearch / LiveVQA / BrowseComp-VL / FVQA / InfoSeek
```

| 模型 | 对应 Agentic Base | OpenSearch-VL | 提升 | 等级 |
|---|---:|---:|---:|---|
| 8B | 42.0 | 56.6 | +14.6 | `P` |
| 30B-A3B | 47.8 | 61.6 | +13.8 | `P` |
| 32B | 48.0 | 63.7 | +15.7 | `P` |

注意：七项平均 `56.6` 与三项消融平均 `71.8` 来自不同评测集合，不能放在同一句话里形成连续提升链。

## 4. 官方训练配置数字

以下属于发布配置，不代表我们必须按相同规模复现：

### SFT

- 模型：Qwen3-VL-8B-Instruct；
- 全参数训练，LLM、ViT 和 projector 均不冻结；
- `cutoff_len=32000`；
- `bf16`，学习率 `2e-5`，8 epochs；
- DeepSpeed ZeRO-3；
- YAML 写有 `ray_num_workers=256`。

来源：`SFT/examples/agentic_full/qwen3_vl_full_sft_8b_ray.yaml`。

### RL

- 发布单机脚本为 1 节点 8 GPU；
- 默认 `adv_estimator=rloo`，不是 `grpo`；
- 每题采样 8 条轨迹；
- prompt batch 256，mini-batch 64；
-最大 prompt 4096，最大 response 70000；
- 256 个并行任务，2048 个并行工具调用；
- Fatal 连续错误阈值为 3。

来源：`RL/rllm/vision_deepresearch_async_workflow/run/qwen3-vl-8b-single-node.sh` 和根 README。

## 5. 简历数字使用规则

### 5.1 个人实验完成前

可以写：

> 基于公开 SearchVL-SFT-36K/RL-8K 数据复现多模态 Agentic SFT 与 Fatal-aware RL 训练链路，并对 Base、SFT、Vanilla GRPO 与 Fatal-aware 策略建立统一评测协议。

不应写：

> 将平均分从 53.7 提升到 71.8。

因为这会自然被理解为个人实验结果。

### 5.2 个人实验完成后

必须新建个人结果表，至少绑定：

- Git commit；
- 模型与 checkpoint；
- 数据 manifest 与 split hash；
- 评测脚本版本；
- benchmark 范围；
- judge 模型和 prompt；
- Seed；
- 原始预测 JSONL；
- 汇总脚本输出；
- W&B/TensorBoard 或控制台日志。

推荐最终写法：

> 在个人缩小复现实验中，Base/SFT/RL 在固定 `[benchmark]`、`[N]` 条测试集上的准确率分别为 `[A]/[B]/[C]`，Fatal-aware 版本相对 Vanilla GRPO 提升 `[Δ]` 个点。
