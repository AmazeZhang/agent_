# 第 1 节：项目背景与研究动机

> 状态：已通过
> 完成日期：2026-08-18
> 对应项目：OpenSearch-VL
> 复习目标：能够解释为什么知识密集型视觉任务需要多模态搜索 Agent，以及 OpenSearch-VL 相对普通 VLM、固定 RAG 和 Search-R1 的价值。

## 1. 一句话概括

OpenSearch-VL 训练的是一个多模态 Deep Research Agent：它围绕图片和问题，自主规划并调用图像处理、图像搜索和文本检索工具，通过 Agentic SFT 获得工具使用冷启动，再通过 Fatal-aware Agentic RL 改进在线探索，并避免长轨迹后期工具故障错误惩罚前期的有效决策。

## 2. 为什么更大的 VLM 仍然不够

普通 VLM 的直接回答可以写成：

```text
a ~ Pθ(a | I, q)
```

它主要依赖：

- 图片中的可见信息；
- 模型参数中存储的知识；
- 当前输入上下文。

但知识密集型视觉问题经常包含以下困难：

1. 答案不在像素中。例如图片能帮助识别桥梁，却不能直接给出开放年份。
2. 参数知识可能缺失、过时或混淆长尾实体。
3. 原图可能模糊、倾斜或关键区域太小，需要先处理图片。
4. 问题可能需要多个实体之间的多跳推理。
5. 最终答案需要外部证据验证，不能只依赖模型猜测。

因此，更大的 VLM 能提高视觉识别和参数记忆能力，但不能从根本上替代外部信息获取和动态工具决策。

## 3. VLM、固定 RAG 与 Agent

| 系统 | 工具/检索由谁决定 | 典型过程 | 核心限制 |
|---|---|---|---|
| 普通 VLM | 不使用外部工具 | 图片 + 问题 → 答案 | 依赖像素和参数知识 |
| 固定 RAG | 预设工程流水线 | 检索 Top-K → 拼接 → 回答 | 模型通常不能改变检索策略 |
| 多模态 Agent | 模型策略 | 观察 → 行动 → 反馈 → 再行动 | 训练和环境更复杂 |

固定 RAG 与 Agent 最本质的区别不是“是否多轮”，而是：

> 工具使用的控制权属于预设流水线，还是属于模型策略。

Agent 可以自主决定：

- 是否调用工具；
- 选择哪一个工具；
- 如何填写参数和搜索关键词；
- 工具失败后如何调整；
- 是否继续验证；
- 什么时候停止并回答。

## 4. 为什么它不只是图像搜索项目

传统图像检索通常关注：

```text
Recall@K、Precision@K、检索排序质量
```

OpenSearch-VL 的最终目标是知识密集型视觉问答的正确率。Image Search 只是完整策略中的一个动作。

项目需要联合完成：

```text
视觉线索定位
→ 图像处理
→ 实体识别
→ 图像/文本检索
→ 证据整合与验证
→ 最终回答
```

其策略可能使用 Crop、Sharpen、Super Resolution、Perspective Correction、Layout Parsing、Image Search、Text Search、Web Search 和 Python Interpreter。

项目优化的不是单个工具本身，而是工具选择、组合、查询构造和停止决策组成的完整问题求解策略。

## 5. 为什么需要专门训练

只给基础 VLM 一份工具说明，模型可能出现：

- 不调用工具，直接猜答案；
- 选择错误工具或生成非法参数；
- 搜索词过宽、重复或偏离任务；
- 图搜后不会通过文本搜索验证；
- 工具失败后无法恢复；
- 证据不足时提前回答；
- 不知道何时停止；
- 多轮后输出格式崩溃。

OpenSearch-VL 因此分为两个主要训练阶段：

### Agentic SFT

通过专家轨迹学习：

- 工具调用格式；
- 基本工具选择策略；
- 如何使用 observation；
- 如何生成最终答案。

### Agentic RL

让当前策略在线采样和比较不同轨迹，探索：

- 更合适的工具顺序；
- 更有效的搜索词；
- 工具失败后的恢复方式；
- 更合理的停止时机。

## 6. 与 Search-R1 的关系

| 维度 | Search-R1 | OpenSearch-VL |
|---|---|---|
| 输入 | 文本问题 | 图片 + 文本问题 |
| 工具 | 主要是文本检索 | 视觉处理、图搜、文本搜索、计算 |
| 环境 | 相对固定的离线检索 | 包含实时联网工具和外部 API |
| Observation | 主要是文本 | 文本 + 新生成图片 |
| 轨迹风险 | 相对较低 | 长轨迹、跨模态、工具故障更多 |
| 核心训练难点 | 搜索查询与文本推理 | 工具规划、跨模态历史和故障信用分配 |

OpenSearch-VL 继承了 Search-R1 的“通过 RL 学习搜索策略”思想，但将它扩展到多模态、多工具和非稳定的在线环境。

## 7. 为什么引出 Fatal-aware RL

在线多模态工具可能出现：

- 搜索 API 超时；
- 网页抓取失败；
- OCR 服务错误；
- 图像下载失败；
- 工具参数或返回格式异常。

一条轨迹可能是：

```text
正确裁剪路牌
→ 正确图搜并识别实体
→ 正确生成文本查询
→ 搜索 API 连续失败
→ 无法生成最终答案
```

这里前缀策略正确，后缀主要由于环境故障而失败。如果普通结果奖励只看到“最终没有答对”，整条轨迹可能获得负 advantage，从而错误惩罚前面的正确决策。

OpenSearch-VL 的处理分为两部分：

### Fatal Mask

定位真正开始崩溃的 fatal step，屏蔽该位置及其后的策略 token，只保留可学习的有效前缀。

### One-sided Advantage Clamp

对 fatal 轨迹执行：

```text
Âᵢ_fatal = max(Âᵢ, 0)
```

- 原 advantage 为正：保留正向强化；
- 原 advantage 为负：截断为零，不惩罚有效前缀；
- 不是把负 advantage 强制变成正奖励。

核心动机是：

> 环境故障不等于整条策略错误，需要更细粒度地保护故障前的有效探索信号。

## 8. 推荐面试回答

> 普通 VLM 主要依赖图片内容和参数知识，但很多知识密集型视觉问题的答案并不直接存在于像素中。例如给定陌生桥梁照片询问开放年份，模型需要先定位视觉线索，通过图像搜索识别实体，再用文本搜索获取和验证外部事实。因此任务需要的是“观察—工具调用—环境反馈—继续决策”的多轮 Agent，而不只是一次视觉推理。
>
> 固定 RAG 也不完全够，因为不同图片需要不同的处理和检索路径。OpenSearch-VL 让模型自主决定工具、参数、搜索词和停止时机。它先通过 Agentic SFT 学习基本工具使用，再通过在线 RL 探索更优策略。由于真实搜索和视觉工具存在超时与失败，项目进一步通过 Fatal-aware masking 和单边 advantage clamp，避免后期环境故障错误惩罚前期有效推理。

## 9. 常见错误表述

### 错误一

“大模型训练时没见过的问题就一定不会回答。”

修正：大模型能够泛化，但对缺失、过时、长尾或需要证据验证的外部知识不可靠。

### 错误二

“Agent 和 RAG 的区别就是 Agent 可以多轮。”

修正：根本区别是工具调用和检索策略是否由模型自主决策。

### 错误三

“OpenSearch-VL 优化图像搜索准确率。”

修正：它优化的是最终问答和完整工具策略；Image Search 只是工具之一。

### 错误四

“Fatal-aware 方法会给故障前缀额外正奖励。”

修正：它屏蔽故障后缀，并将 fatal 轨迹的负 advantage 截断为零；只有原本为正的 advantage 才继续产生正向强化。
