- 基于 Qwen3-VL-8B 与公开 SearchVL-SFT-36K/RL-8K 数据构建多模态 Deep Research Agent，接入视觉处理、OCR、图像/文本搜索、网页访问及 Python 等工具，搭建 Agentic SFT→在线多轮 Rollout→复合奖励→RLOO/GRPO 的两阶段训练链路。

## 3. 第二条文案：SFT Mask、异步 RL 与复合奖励

### 3.1 SFT 中 Observation 为什么不计算 Loss

数据角色映射：

```text
SFT/data/dataset_info.json
SFT/src/llamafactory/data/converter.py
SFT/src/llamafactory/data/template.py
```

关键过程：

1. `dataset_info.json` 将工具返回标记为 `observation`；
2. `converter.py` 将其转换为 `Role.OBSERVATION`；
3. `template.encode_multiturn()` 把 user/observation 组织为 source，把 assistant/function 输出组织为 target；
4. `SFT/src/llamafactory/data/processor/supervised.py:69-97` 对 source label 填入 `IGNORE_INDEX=-100`，target label 保留真实 Token ID；
5. Cross Entropy 因而只监督模型动作，不监督外部搜索结果和 OCR 文本。

核心代码：

```python
if self.data_args.train_on_prompt:
    source_label = source_ids
else:
    source_label = [IGNORE_INDEX] * source_len

target_label = target_ids
```

学习验收：拿一条真实 ShareGPT 轨迹，逐段标出 user、assistant、observation、function，并说明哪些 Token 的 label 是 `-100`。

## 4. 第三条文案：Fatal Step、Prefix Mask 与 Clamp

这部分是项目最重要的算法与源码主线。

### 4.1 Fatal Step Detection

位置：

```text
RL/rllm/vision_deepresearch_async_workflow/deepresearch_workflow.py:359-400
```

关键函数：

```python
_find_fatal_step_index(steps, termination)
```

逻辑：

1. 连续错误计数从 0 开始；
2. 工具错误时加 1；
3. 中间出现成功步骤则清零；
4. 连续 3 次错误时，将第一次错误所在步骤作为 `fatal_start`；
5. 非正常结束但没有连续错误时，把 fatal 点标在最后一个已有步骤之后，保留全部已有前缀但启用 Clamp。

### 4.2 Fatal 后缀 Token Mask

位置：

```text
RL/rllm/rllm/engine/agent_workflow_engine.py:24-48
```

关键函数：

```python
_apply_fatal_step_mask(response_mask, fatal_step_index)
```

它遍历 response mask 中连续的 Assistant Token 区块，从第 `fatal_step_index` 个动作区块开始把后续 Mask 全部置零。

数据接入位置：

```text
agent_workflow_engine.py:364-489
```

这里把 `is_fatal` 和 `fatal_step_index` 从 Episode 信息转换为 Token Mask，并在返回给 verl 的 batch 中写入：

```text
response_mask
traj_rewards
step_rewards
is_fatal
```

### 4.3 One-sided Advantage Clamp

位置：

```text
RL/rllm/rllm/trainer/verl/agent_workflow_trainer.py:488-500
```

核心代码：

```python
batch.batch["advantages"][_fi].clamp_(min=0.0)
batch.batch["returns"][_fi].clamp_(min=0.0)
```

含义：

- Fatal 轨迹仍参与组内 Reward/Advantage 统计；
- Fatal 轨迹 Advantage 为正时，保留故障前缀的正向更新；
- Advantage 为负时截断为 0，不用环境故障导致的负信号惩罚可能正确的前缀；
- `fatal_step_index=0` 时没有可恢复前缀，Mask 全零，退化为 Hard Mask。
